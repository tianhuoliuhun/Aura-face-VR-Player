# Huawei VR Glass 播放器交互设计（v1）

> 适用设备：华为 VR Glass（3DoF 眼镜 + 3DoF 手柄，手机端「华为 VR」App 内运行）
> 与 2D 模式的关系：**完全独立的一套 UI**，不复用 `PlayerControlBar` / `SubtitleOverlay`
> 原因见 §7「为什么不能复用 2D 组件」。

---

## 1. 设计约束（决定了后面所有取舍）

| 约束 | 影响 |
|---|---|
| **3DoF（有旋转姿态，无位置追踪）** | ⚠️ **可以做「手柄朝向射线」** —— 3DoF 手柄有 IMU，能给出**朝向**，射线原点固定在头部/眼镜、方向取手柄姿态即可。**但不能做「手伸出去点」的位置偏移**（无平移），也不能做「手柄悬浮靠近控件」的悬停（手不会被追踪到空间位置） |
| **手柄：select（点击）+ 触摸板 + 姿态** | 交互原语：**射线指向 + 点击**（指向性），以及**时序**（单击/双击/长按） |
| **眼镜无扬声器、无麦克风** | 音频走手机，交互设计不涉及语音 |
| **双眼单屏、屏幕已旋转** | UI 必须在**双眼各自视口内**绘制；不能依赖 Android View 层（2D Compose 看不到） |

**核心结论（已按用户反馈修正）**：
- **主交互范式 = 手柄射线指向 + 点击**（与主流 6DoF 头显一致的操作习惯），
  这是用户明确要求的，且 3DoF 手柄**技术上支持**（有姿态即可）
- **射线做不到的部分**：无平移 → 不能「靠近了才高亮」；射线是**纯方向**的，
  原点绑定在头部，所以准星位置随头部转动而变 —— 需要适配（见 §4 准星设计）
- **焦点式导航保留为兜底**：无手柄 / 手柄姿态不可用时，仍可用「单击循环切换焦点」操作

**实现依赖**：`xrCreateActionSpace`（aim pose，路径 `/user/hand/*/input/aim/pose`）
+ 每帧 `xrLocateSpace` 取姿态 → 用姿态方向生成射线（两个入口 v2.0.199 已加入 loader）。
⚠️ 待真机确认华为手柄是否提供 `aim/pose`；若不提供，则回退到「手柄姿态直接给出朝向」的近似。

## 2. 核心交互流程

```
插上 VR Glass / 从 VR 桌面启动
        ↓
  视频自动全屏播放（不做任何遮挡，默认无准星）
        ↓
  ┌─── 单击手柄 ──→ 呼出「控制条」+ 显示准星
  │        ↓
  │   控制条出现后（**射线指向 + 单击**）：
  │     · 手柄朝向移动准星 → 落在控件上即高亮（悬停反馈）
  │     · 单击               → 确认（触发准星所指项）
  │     · 无手柄时兜底：左右拨触摸板移动焦点 + 单击确认
  │     · 5 秒无操作         → 控制条与准星一起淡出
  │        ↓
  ├─── 长按手柄（≥0.8s）─→ 呼出「主菜单」（视野正中，半透明面板）
  │        ↓
  │   主菜单：继续播放 / 打开文件 / 视角设置 / 字幕设置 / 画面设置 / 退出
  │        ↓
  │   「打开文件」→ 最近播放列表 →（搜索）→ VR 键盘（见 §12）
  │
  └─── 双击手柄 ──→ 切换「沉浸 / 影院」布局（见 §5）
```

**状态机只有三个**：`播放中（无 UI）` ⇄ `控制条` ⇄ `主菜单`，
另有 `打开文件面板`（含键盘）作为主菜单的**就地展开**（不算独立层级，返回键回主菜单）。

**准星策略**：无 UI 时**不显示准星**（避免遮挡视频）；呼出 UI 后显示，
5 秒无操作随 UI 一起淡出。这样既保留射线交互的直观，又不干扰观影。

## 3. 控制器操作映射（手柄）

> **主交互 = 射线指向 + 点击**：手柄朝向决定准星位置，准星落在控件上即高亮，单击确认。
> 下表的「单击/双击/长按」是**时序扩展**，「触摸板」是**无姿态 / 姿态不稳时的兜底通道**。

| 操作 | 时序 | 动作 | 备注 |
|---|---|---|---|
| **射线指向** | 持续 | 移动准星；落在控件上高亮（悬停反馈） | 主交互。仅在有 UI 时显示准星 |
| **单击** | < 0.4s | 无 UI 时：呼出控制条+准星<br>有 UI 时：确认准星所指项 | 唯一的主确认操作 |
| **双击** | 两次间隔 < 0.35s | 切换沉浸/影院布局 | 高频操作，给最短路径 |
| **长按** | ≥ 0.8s | 呼出 / 收起主菜单 | |
| **触摸板左右** | — | **兜底**：移动焦点（等价于移动准星） | ⚠️ 需华为专有 profile，见 §8 |
| **触摸板上下** | — | 调节音量 | 同上 |
| **触摸板滑动（快滑）** | — | 快退 10s / 快进 10s | 同上 |

**按下沿去重**：所有「单击」必须基于 `pressedEdge`（刚按下）触发，不能基于「按住」状态，
否则按住期间会每帧重复触发 —— 这一点在 v2.0.200 的 `pollVrInputOnce()` 已实现。

**时序判定的实现位置**：在 Kotlin 侧（`HuaweiVrActivity` / `VrInputRouter`）做，不在 native。
native 只负责上报「按下/抬起 + 时间戳 + 手柄姿态」，判定逻辑属于业务。

**射线生成**：`xrLocateSpace`（aim pose，`/user/hand/*/input/aim/pose`）取手柄姿态，
以**头部为原点、手柄朝向为方向**生成射线，与 UI 层求交得到命中项。

## 4. 播放控制布局（控制条）

沉浸式 VR 里，控制条**不应**是 2D 视频软件那样贴在屏幕底边 —— 那会让用户必须
低头看边缘。主流 VR 视频软件（Skybox / 4XVR / DeoVR）的做法一致：**控制条浮在
视线前方略下方，随视线轻微跟随，始终可读**。

```
                视线中心（画面正中）
                       │
                       ▼
        ┌──────────────────────────────────┐
        │   ← 10s    ▶/⏸    → 10s    ⊞     │   ← 控制条（浮于视线正下方约 12°）
        └──────────────────────────────────┘
         ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━   ← 进度条（细，贯穿全宽）
              00:12:36              01:47:02
```

- **进度条细而长**：VR 里宽视野下，粗短进度条的时间定位精度很差
- **按钮间距大**：焦点式导航必须让「当前焦点」在视野中一眼可辨（高亮描边 + 轻微放大）
- **只有 4 个按钮**：`-10s` / `播放暂停` / `+10s` / `更多`（打开主菜单）
  —— 按钮越多，焦点移动越慢，越不符合「顺畅」
- **`更多` 而非平铺全部功能**：把低频项（字幕/视角/画面）收进主菜单

**自动隐藏**：5 秒无操作淡出（不做「立即隐藏」，避免误触后找不到）。淡出用透明度渐变，不做位移动画（VR 里位移动画易引发不适）。

## 5. 视角切换（沉浸 / 影院）

| 模式 | 画面 | 适用 |
|---|---|---|
| **沉浸（默认）** | 视频填满视野，随头部转动（3DoF） | 全景 / 180° / 普通视频「沉浸看」 |
| **影院** | 视频贴在一块「虚拟银幕」上，银幕固定于正前方，**背景压暗** | 普通 2D 视频、需要长时间观看（减少转头疲劳） |

- **切换方式：双击手柄**（高频，给最短路径）
- 切换**不做插值动画**，直接切换（VR 里视野突变比渐变更不易晕）
- 影院模式的银幕尺寸可记忆（用户调过一次就记住）
- 全景视频（2:1 等距圆柱）**强制沉浸**，不允许切影院（否则会 letterbox 压成窄带 —— 这是本项目已踩过的坑）

## 6. 菜单呼出方式（主菜单）

- **呼出**：长按手柄 ≥ 0.8s
- **位置**：视野正中，距离约 2m 处，**半透明面板（约 85% 不透明）**，背后的视频仍可见（不打断沉浸感）
- **关闭**：再长按一次 / 焦点移到「继续播放」并单击 / 10 秒无操作自动关闭
- **布局**：2 列 3 行的网格，6 个入口（见 §2 状态机）
- **不做二级菜单**：点进任一项后，该项的**具体参数**直接以「滑块/选项」形式**在同一个面板内展开**（替换网格），返回键位固定在面板左下

**为什么不做多级**：3DoF 手柄只有点击，多级菜单的「返回」会让用户迷路；
单层 + 就地展开是最不容易迷失的结构。

## 7. 字幕（VR Glass 专属设计）

### 为什么不能复用 2D 的 `SubtitleOverlay`

2D 字幕层是 Compose 绘制在视频 View 之上的。VR 模式下：
- 画面由 **native GL 逐眼绘制**，Compose 层根本不在渲染路径里 → 看不到
- 即使强行合成，也是**平面贴在眼前**，而 VR 里视频可能铺满 360° —— 字幕会飘在错误的位置

**结论：VR 字幕必须在 native GL 侧绘制，且是独立的渲染层。**

### 设计要点

| 项 | 设计 | 理由 |
|---|---|---|
| **位置** | 视线正下方约 **15°**，不随视频内容移动 | 与「沉浸 vs 影院」无关，永远可读 |
| **距离感** | 渲染在约 **1.5m** 处（比银幕近） | 保证不被人脸/画面细节干扰，且不用转头 |
| **跟随** | **跟随头部**（渲染在头锁定空间，不是世界空间） | 转头时字幕不跑掉，这是 VR 字幕与 2D 最大的不同 |
| **行数** | 最多 **2 行**，超出截断 | 3 行以上会挡住画面中心 |
| **字号** | 视野角约 **1.6°**（约等于 2D 下 24px @ 1m） | 太小看不清，太大挡画面 |
| **背景** | 文字**带描边**（黑边 2px），**不加**实底色块 | 实底色块在 VR 里非常突兀 |
| **颜色** | 默认浅黄白（#F5F0E0），可切纯白 | 略偏暖在暗场景更柔和不刺眼 |
| **双眼** | 左右眼**各自独立绘制**（同内容） | 单眼绘制会破坏立体感 / 某些实现直接看不到 |

### 与 2D 字幕的关系
- **共用同一份字幕数据**（`SubtitleOverlay.kt` 的解析结果、时间轴同步逻辑）
- **不共用渲染**（2D 走 Compose，VR 走 native GL）
- 配置项（字号档位 / 颜色 / 描边开关 / 延迟微调）**共用**，在 VR 主菜单的「字幕设置」里暴露同样的档位

| **VR 版字体渲染** | ⬜ 待做：native 侧要么打包字体图集，要么用 FreeType（需评估体积/复杂度）。中文字形多，**图集方案不现实**，倾向 FreeType |

## 9. 明确不做的事（避免过度设计）

- ❌ **不做「手伸出去点」的位置交互**：3DoF 无平移追踪，做不到（射线方向可做，位置不可做）
- ❌ **不做裸手手势识别**：华为 VR Glass 无手部追踪摄像头
- ❌ **不做 3D 空间中的视频任意摆放**：本产品是「看视频」，不是「VR 空间应用」
- ❌ **不做多窗口 / 分屏**：视野有限，分屏会让每个视频都太小
- ❌ **不做位移动画**：VR 里 UI 位移易引发前庭不适，一律用透明度变化

## 11. VR 独立播放器（用户决策：归 HuaweiVrActivity）

### 决策
**VR 模式使用自己独立的播放器实例**，由 `HuaweiVrActivity` 持有 —— 不复用
`VRPlayerScreen` 里那个。这解开了 v2.0.200 遗留的「控制通道缺失」阻塞。

### 为什么这样划分是合理的
| 维度 | 2D 模式（VRPlayerScreen） | VR 模式（HuaweiVrActivity） |
|---|---|---|
| UI 框架 | Jetpack Compose | native GL（XR 会话内逐眼绘制） |
| 渲染归属 | View 树 | `VRGLRenderer` + 华为 XR 会话 |
| 播放器 | 主界面持有 | **VR Activity 自己持有** |
| 生命周期 | 随主界面 | 随 VR 会话（插拔眼镜） |

两者**共享的只有数据**（文件列表、字幕解析结果、设置项），**不共享播放器实例**。
好处：VR 会话崩溃/退出不会影响主界面；插拔眼镜不需要迁移播放状态。

### 结构
```
HuaweiVrActivity
  ├── VRGLRenderer          （已有的：逐眼 GL 绘制）
  ├── VrPlayer              （新增：独立的播放器封装）
  │     · 与 2D 侧用同一套解码后端，但独立实例
  │     · Surface 接到 VR 渲染管线（已有 onVideoSurfaceCreated 通路）
  ├── VrUiLayer             （新增：native GL 的 VR UI —— 控制条/主菜单/准星/键盘）
  └── VrInputRouter         （新增：手柄事件 → 时序判定 → 焦点/射线命中 → 业务动作）
```

⚠️ 播放器后端选型（ExoPlayer 还是现有封装）需在实现时对齐 2D 侧的做法，避免两套解码配置分叉。

## 12. VR 键盘（用户决策：加）

主菜单的「打开文件」需要一个能在 VR 里输入的东西 —— 但**不加全键盘**。

### 设计
| 项 | 方案 | 理由 |
|---|---|---|
| **呼出** | 主菜单 →「打开文件」→ 顶部出现**搜索框**，下方浮出键盘 | 只有需要输入时才出现，不干扰浏览 |
| **布局** | **3 行 × 10 列字母 + 数字行**（共 4 行）；不做全尺寸 QWERTY 的符号页 | VR 里逐字母射线点选很慢，符号页几乎用不到 |
| **键位大小** | 每键视野角约 **3.5°** | 太小射线点不中；太大会超出一屏 |
| **输入方式** | **射线指向 + 单击**（主）；触摸板左右移动焦点 + 单击（兜底） | 与 §1 主范式一致 |
| **大小写** | 「⇧」键切换，不做长按 | 长按在 VR 里难判定 |
| **删除** | 「⌫」单击删一个字符；**长按 ⌫ 连续删除** | 唯一允许长按的键（高频纠错） |
| **回车** | 「→」键确认搜索 | |
| **位置** | 键盘浮在**视线下方约 25°**，不遮挡搜索框与结果列表 | 键盘挡住结果就没法选了 |
| **结果列表** | 键盘上方显示匹配文件（最多 8 条），射线点选即播放 | |

### 备用输入通道（更省事的路径）
- **手机端输入**：VR 时手机就在手上 —— 可以在手机上弹一个输入框，输入结果同步到 VR。
  **体验远好于在 VR 里逐字母点**。
- 建议：**默认用「手机输入」，VR 键盘作为无手机场景的兜底**。
  （待你确认是否接受这个折中；若不接受，就只做 VR 键盘。）
- ⚠️ 另：若 2D 模式已选好片，VR 直接续播，则**根本不需要输入** —— 这是最顺的路径，
  所以「打开文件」应保留但**不设为默认焦点**。

### 与「打开文件」的关系
用户明确要求主菜单保留「打开文件」（不做成「只在 2D 选片」）。因此：
- 主菜单 6 项调整为：继续播放 / **打开文件** / 视角设置 / 字幕设置 / 画面设置 / 退出
- 「打开文件」进去后：**最近播放列表（优先）→ 搜索（呼出键盘）→ 浏览目录**

## 13. 待确认问题（需要你拍板）

1. **VR 键盘 vs 手机输入**：VR 里逐字母射线点选很慢，手机输入快得多。
   是「默认手机输入、VR 键盘兜底」，还是「只做 VR 键盘」？
2. **射线准星的呈现**：3DoF 手柄射线的原点是头部，准星会随**转头**移动而移动
   （不像 6DoF 那样靠手）。是否接受「准星固定在视野中心、靠转头瞄准」这种形态？
   若不接受，需要改用「手柄姿态相对头部的偏角」来生成射线（更接近直觉，但华为手柄
   姿态数据是否足够稳定需真机验证）。
3. **触摸板是否可用**：决定兜底操作链路的丰富程度（需真机确认 profile path）。

## 14. 参考同类产品：JellyQuest（Quest 上的 Jellyfin 影院应用）

仓库：`https://github.com/JoeCotellese/JellyQuest`（Meta Spatial SDK + Kotlin + ExoPlayer）
它解决的正是同一类问题（在 VR 里播媒体库），以下几个设计**值得直接借鉴**：

### 14.1 Quick Connect —— 免打字登录（印证了「手机输入」路线）
JellyQuest 用 Jellyfin 的 Quick Connect：**在手机/电脑上授权，VR 里不用输入任何文字**。
这与本文 §12 提出的「手机输入优先、VR 键盘兜底」**思路完全一致**，且被成熟产品验证。
**对我们的启示**：与其做 VR 键盘，不如优先做「手机扫码 / 局域网配对」类输入通道；
VR 键盘降级为最后兜底。

### 14.2 影院预设 + 座位位置（影院模式的成熟形态）
JellyQuest 提供 4 种影院（Screening Room / Multiplex / PLF / IMAX）× 3 个座位（前/中/后），
银幕尺寸从 32" 到 22m —— 本质是「**银幕尺寸 + 距离**」的组合预设。
**对我们的启示**：§5 的「影院模式」不应只有一种，而应做**预设列表**
（如：手机屏 / 电视 / 小影院 / IMAX × 前/中/后排），用户点一下就切。
实现上只是改投影面的宽度和距离两个数，成本低、体验收益大。

### 14.3 CylinderLayer —— 曲面层渲染（⭐ 最有价值的一条）
JellyQuest 用 **CylinderLayer** 播放视频：视频画在一块**弯曲的曲面层**上，
由**合成器（compositor）直接合成**，不走应用 GL —— 获得原生级画质且零合成开销。
OpenXR 对应扩展：**`XR_KHR_composition_layer_cylinder`**。
**对我们的启示（若华为 Runtime 支持）**：
- 视频不再画进 swapchain 纹理再上屏，而是交给合成器的曲面层
- **清晰度更好**（绕过一次采样）、**GPU 负担更低**、抗畸变更好
- ⚠️ 前置：需真机确认华为 Runtime 是否支持该扩展（`xrEnumerateInstanceExtensionProperties` 可查）
- ⚠️ 与本方案的关系：现有 GL 渲染路径保留为兜底；cylinder layer 作为增强路径

### 14.4 Compose 画 UI → 贴成 VR 纹理（⭐ 解决我们「native 无字体」的困境）
JellyQuest 的库浏览/影院选择面板全是 **Compose**，通过 Meta Spatial SDK 的 Panel
机制把 Compose 内容**渲染成纹理贴进 VR**。
Meta 的 Panel 是专有的，但**思路是通用的**：
- 用 Android **Canvas / Compose 画到一个 `SurfaceTexture`**（离屏）
- 该纹理作为普通 GL 纹理，贴在 VR 里的 UI 平面上（我们现成的 quad 绘制路径）
**对我们的启示**：
- 控制条/菜单/字幕可以**用 Compose/Canvas 画**——中文、复杂 UI 全都解决，
  **不需要 FreeType**，也和 2D 侧的 UI 代码风格统一
- 实现代价：一条「Canvas → SurfaceTexture → GL 纹理 → quad」的通路
  （我们已有 SurfaceTexture 通路，复用度高）
- ⚠️ 注意每帧重绘的成本：UI 变化时才重绘纹理，静止帧直接复用

### 14.5 控制器按键映射对照
JellyQuest：X=切库浏览、A=切影院、B=播放暂停、Trigger=确认。
**对我们的启示**：华为手柄没有多按键（只有 select + 触摸板），
「一键多义 + 时序」是我们已有的方案，无需照搬其按键布局。

### 14.6 结论
| JellyQuest 的做法 | 我们怎么做 |
|---|---|
| Quick Connect 免打字 | 手机输入/配对优先，VR 键盘兜底 |
| 影院预设 × 座位 | 影院模式做预设列表（银幕尺寸+距离） |
| CylinderLayer 视频渲染 | 查华为是否支持 `XR_KHR_composition_layer_cylinder`，支持则做增强路径 |
| Compose Panel 画 UI | **Canvas→SurfaceTexture→GL quad**：解决中文字体问题，推荐采纳 |
| 多按键手柄 | 不适用（华为只有 select+触摸板），保持时序方案 |
